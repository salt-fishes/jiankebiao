# rulepack-dev — 解析规则包开发工作台

给「想让自己学校/教务系统的课表能被简课表识别」的用户准备的 AI 辅助开发工作台。

## 它解决什么问题

简课表导入课表（PDF/Excel/截图）时，「导出文本 → 课程字段」的解析规则因教务系统而异。
应用内置了少量规则包（正方、图标行式等），但没有收录的格式以前只能等发版。
现在：**用你的 AI 编码工具（Claude Code / ZCode / Cursor 等）加载本目录，对着你的课表
文件对话式产出一个规则包 JSON，导入应用即可**——不需要改应用代码、不需要联网。

## 目录内容

| 文件 | 用途 |
|---|---|
| `SKILL.md` | AI agent 的工作流指令（把本目录喂给你的编码工具的入口） |
| `schema.json` | 规则包格式规范 v1（与应用内 `ParseRulePack.SCHEMA_VERSION = 1` 对应） |
| `knowledge.md` | 教务系统导出格式与 OCR 变体的领域知识（规则提炼时参考） |
| `validate.py` | 纯标准库校验器：结构 / 安全上限 / 正则可编译 / 指纹自检 |
| `examples/` | 占位数据示例包（ zfsoft 斜杠键值式 + 图标行式）。**这两个是内置包的参考模板**：复制它们改新包时必须换 `id`，否则应用会拒绝导入（校验器同样会报「id 与内置包重名」） |

## 快速开始

1. 把你的课表导出文件（PDF / Excel / 截图）放在**本机任意临时目录**；
2. 让你的 AI 编码工具读取并遵循 `SKILL.md`，并告诉它你的文件路径；
3. 按对话流程产出 `rulepack.json`；
4. 手机端「我的 → 解析规则包 → 从文件导入规则包（JSON）」导入；
5. 用你的课表文件走一遍导入流程验证字段是否正确。

## 红线（与应用内校验一致，违反会被拒绝导入）

- 规则包是**纯数据**：只允许词表、正则、映射，没有任何可执行逻辑；
- **禁止真实个人信息**：示例与测试一律用占位数据（如「张三」），不要把含真实
  姓名/学号的课表内容写进规则包或提交到任何仓库；
- 外部正则受限：单条 ≤ 200 字符、词表 ≤ 24 条、词条 ≤ 24 字符；
  应用导入时会重新编译每条正则，编译失败即拒绝。

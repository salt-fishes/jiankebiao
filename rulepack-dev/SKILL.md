# SKILL：简课表解析规则包开发

> 把本文件交给 AI 编码工具（Claude Code / ZCode / Cursor 等）作为工作流指令。
> 目标：基于用户的一份课表导出文件，产出可通过校验、可在简课表内正确解析的
> 规则包 JSON（schema v1，见 `schema.json`）。

## 红线（每一步都必须遵守）

1. **隐私**：用户的课表样本可能含真实姓名/学号。样本文件只放在系统临时目录，
   绝不复制进任何仓库/工作目录；产出与测试中出现的课程名、教师名一律替换为
   占位数据（如「张三」「高等数学A1」这类通用名）。
2. **纯数据**：规则包只能包含词表、正则、映射。不要尝试在 JSON 里放任何代码。
3. **安全上限**：单条正则 ≤ 200 字符；词表 ≤ 24 条、每条 ≤ 24 字符。
   优先用简单正则——灾难性回溯会让应用卡死。

## 工作流（按序执行，不可跳步）

### 第 1 步：取得样本并判断类型

让用户提供课表文件路径。先判断类型：

- **PDF 有文字层**：`pdftotext -layout <file> -` 或 python `pypdf` 能提出中文文本 → 直接分析文本；
- **PDF 无文字层**（老教务系统把文字画成像素/矢量，提取结果为空或乱码）：
  说明必须走应用内「渲染+OCR」路线，规则包的锚词应按 OCR 输出形态来写。
  让用户在应用内试导入一次并描述结果，或改用**课表截图**作为样本（OCR 路线相同）；
- **Excel (.xls)**：当前版本班级课表 Excel 走独立解析器（暂不受规则包控制），
  如格式不兼容请如实告知用户暂不支持；
- **截图**：按图片中的文字形态分析（这是最常见路径）。

### 第 2 步：提炼格式特征

从样本文本回答以下问题（全部有答案才继续）：

1. 表头锚词：网格表头是否有稳定词（如「时间段」「节次」）？没有 → `headerAnchor` 留空，
   并告知用户：该格式仅截图识别可用（PDF 网格重建需要锚词）。
2. 星期列名模式：「星期一」/「周一」/「MON」？→ `dayPattern`。
3. 噪声行：上午/下午/晚上、图例、打印时间等整行丢弃的词 → `labelWords` / `legendWords`。
4. 课程块起始：课程名行是否以类型标记结尾（★○●◇ 等）？→ `typeMarks`。
   截图单卡场景可留空。
5. 字段形态属于哪种（可并存）：
   - **键值式**：`校区:下沙/教师:张三` 这类 `key:值` 链 → `keyMap`（key → 语义字段）；
   - **行前缀式**：`📍 教室` / `👤 教师` / `◎ (1-2节)1-4周` → `linePrefixes`（前缀 → 语义字段）；
   - **位置式**：无标记，末行短中文行是教师 → `positionalTeacher: true`。
6. 节次与周次写法：`(1-2节)`？`第1-2节`？`1-4周`？`第3周(单)`？
   → 调整 `sectionsPattern` / `weeksPattern` / `paritySingle` / `parityDouble`。

语义字段白名单（keyMap 与 linePrefixes 的值只能取自）：
`campus, building, room, teacher, classNo, composition, credit, sections`

### 第 3 步：编写规则包 JSON

以 `examples/` 为模板生成。要求：

- `id`：小写字母数字与 `-_ .`，如 `qz-icon`（不要与内置 `zfsoft` / `icon-grid` / `generic` 重名）；
- `name`：给人看的名字，如「强智教务（XX大学）」，≤ 40 字；
- `match.anyOf`：3~5 个**在该系统导出中必然出现、别的系统很少出现**的子串，
  如字段 key「教学班组成」、特征词「高等学校教师」、表头「时间段」。`minHits` 建议 2；
- 正则全部用最简形态；中文标点注意全角变体（参考 `knowledge.md`）。

### 第 4 步：校验

```bash
python validate.py rulepack.json --sample sample.txt
```

- 无 `--sample` 时只做结构/上限/正则校验；
- 有 `--sample` 时额外做指纹自检（anyOf 命中数 ≥ minHits）与节次/周次正则抽样提示；
- 校验器与手机端行为可能存在细微正则方言差异（Python re vs Java regex），
  以应用导入为准；校验通过后仍必须完成第 5 步。

### 第 5 步：真机验证

1. 手机「我的 → 解析规则包 → 从文件导入规则包（JSON）」导入 `rulepack.json`；
2. 用用户的课表文件走「新建课表 → 导入文件/截图识别」完整流程；
3. 在导入确认弹窗逐条核对：课名 / 教师 / 教室 / 节次 / 周次；
4. 有错回到第 2 步修规则，重新导出 JSON 再导入（同 id 会覆盖）。

全部通过后，把最终 JSON 交给用户，并提醒：文件含个人课表数据，请勿分享原始样本。

# SKILL：简课表解析规则包开发

> 把本文件交给 AI 编码工具（Claude Code / ZCode / Cursor 等）作为工作流指令。
> 目标：基于用户的一份课表导出文件/截图，产出可通过校验、可在简课表内正确解析的
> 规则包 JSON（schema v2，见 `schema.json`）。

## 红线（每一步都必须遵守）

1. **隐私**：用户的课表样本可能含真实姓名/学号。样本文件只放在系统临时目录，
   绝不复制进任何仓库/工作目录；产出与测试中出现的课程名、教师名一律替换为
   占位数据（如「张三」「高等数学A1」这类通用名）。
2. **纯数据**：规则包只能包含词表、正则、映射。不要尝试在 JSON 里放任何代码。
3. **安全上限**：单条正则 ≤ 200 字符；词表/规则 ≤ 24 条、每条 ≤ 24 字符。
   优先用简单正则——灾难性回溯会让应用卡死。

## 工作流（按序执行，不可跳步）

### 第 1 步：取得样本并判断格式族

让用户提供课表文件路径。先判断类型（详见 `knowledge.md` 格式族表）：

- **PDF 有文字层**：`pdftotext -layout <file> -` 能提出中文文本 → 直接分析；
- **PDF 无文字层**（像素字）：走应用内「渲染+OCR」，规则判据按 OCR 输出形态写；
- **教务网页大截图**（正方等）：需要导入首页课表 → 图标行式，基于内置 `icon-grid` 改
  （`screenshot: true`，文件入口自动走相册）；
- **App 课程卡竖屏截图**（WakeUp 类彩色卡片）：用户场景是**「课表对比」找共同空闲**，
  只需占用识别（不依赖规则包），**不要为它建导入规则包**；先与用户确认真实需求；
- **Excel (.xls)**：独立解析器（暂不受规则包控制），如实告知暂不支持。

### 第 2 步：提炼格式特征

从样本文本回答以下问题（全部有答案才继续）：

1. 指纹：哪些子串「该系统必然出现、别的系统很少出现」？与既有截图包做互斥检查；
2. 块起始：课程标题行的形状（行尾标记 / `(类型)` 后缀 / 其他）？→ `courseStart`；
3. 字段形态：键值链 / 行前缀 / `@` 前缀 / 位置裸行？→ `fieldRules`（或 v1 糖 keyMap）；
4. 节次周次写法 → `sectionsPattern` / `weeksPattern`（卡面无节次 → 留空）；
5. 是否截图格式 → `screenshot: true`（否则文件入口不会走相册选图）。

### 第 3 步：编写规则包 JSON

以 `examples/` 为模板生成（appcards-sample / zfsoft-sample / icon-grid-sample）：

- `id`：小写字母数字与 `-_`，不与内置重名；
- `courseStart`/`fieldRules` 一律有序、先到先得；每条规则给 `name` 便于诊断定位；
- 正则全部用最简形态；中文标点注意全角变体（参考 `knowledge.md`）。

### 第 4 步：校验 + 模拟器试跑（本地闭环，无需真机反复试）

```bash
python validate.py rulepack.json --sample sample.txt --simulate cells.txt
```

- `--sample`：指纹自检（anyOf 命中数 ≥ minHits）；
- `--simulate`：镜像应用内执行器逐格试跑，输出每格字段值、命中规则、未入块行；
  cells.txt 用应用私有目录 `ocr_debug_image.txt` / `ocr_debug.txt` 的逐格文本段
  （让用户导出，或按截图内容手写占位样本）；
- 迭代规则直到每个单元格的字段全部命中且无未入块行；
- 校验器与手机端可能存在正则方言差异（Python re vs Java regex），
  以应用导入为准；校验通过后仍必须完成第 5 步。

### 第 5 步：真机/模拟器验证

1. 手机「我的 → 解析规则包 → 从文件导入规则包（JSON）」导入 `rulepack.json`；
2. 用用户的课表文件走完整导入流程（截图包会从相册选图）；
3. 在导入确认弹窗逐条核对：课名 / 教师 / 教室 / 节次 / 周次；
4. 有错回到第 2 步修规则（同 id 重导覆盖）。

全部通过后，把最终 JSON 交给用户，并提醒：文件含个人课表数据，请勿分享原始样本。

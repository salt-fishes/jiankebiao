# 教务系统课表格式与 OCR 变体知识库

写规则包前先读。这些是从真实导出与 OCR 实战里踩出来的规律。

## 内置格式族与「两种截图、两种需求」

| 内置包 | 格式 | 指纹（anyOf） | 关键判据 |
|---|---|---|---|
| `zfsoft` | 正方 PDF（文本层/像素字 OCR） | 校区: 楼号: 教学班 选课备注 时间段 | 键值式 keyMap；★○●◇ 行尾标记 |
| `icon-grid` | **正方教务网页大截图** | 高等学校教师 未排地点 时间段 | 图标行 ◎📍👤🏠 + 职称括注 + 教学班编号；`(N-M节)N-M周` 文本 |
| `qz` | 强智 PDF（像素字） | (理论) (实践) (实验) 【 | `课名(类型)` 后缀；`教师【周次】`同行；位置式教师/教室 |

**两种竖屏截图是两种需求，不要为卡片截图建导入规则包**：

- **正方教务网页大截图** → 需要导入首页课表（字段解析）→ `icon-grid` 包（`screenshot: true`，
  文件入口自动走照片选择器）；
- **App 课程卡竖屏截图**（WakeUp 类彩色卡片，`课名★/教师/@地点`）→ 只用于
  **「课表对比」找共同空闲**——占用识别（OccupancyParser）按色块/文字聚类判定，
  不依赖规则包，不需要也不应该做字段导入包（卡面无节次周次、窄卡片 OCR 碎行，
  字段解析不可靠）；给这类截图写导入包前先与用户确认真实需求。

给新截图格式写导入包时：确认它是「结构化课表导出的截图」（卡片间有网格语义），
声明 `screenshot: true`，并与 `icon-grid` 做指纹互斥检查（minHits=2 起步，
两条样本互相跑对方的 anyOf）。

## v2 规则写法（courseStart / fieldRules）

执行器语义（`ScheduleParser`，模拟器 `validate.py --simulate` 与其同构）：

1. **块起始** `courseStart`：有序规则，第一条在行内 `find` 命中即开新块；
   `nameGroup` 取课名，`typeGroup`+`typeMap` 或 `type` 定类型；
   命中行中**标记之后的剩余文本**按续行处理（教师/周次可写在同一行）；
2. **字段** `fieldRules`：按序执行，**字段先到先得**（已填则跳过）；
   - 无 `linePrefix` 且无 `line`：在「正文」（未命中前缀的续行拼接、去空白、
     全角括号归一）中 `find`；
   - `linePrefix`：路由以该前缀开头的行（结构性剥离）；
   - `line: "first"/"last"`：逐行扫描全部续行（OCR 图标常被吞，行形状比前缀可靠）；
   - 变换白名单：`stripTrailingParen`（剥尾部括注）、`splitCampus`（按空格拆
     campus/room，**首段须 ≤5 字纯 CJK**）、`cleanTeacher`（从首个职称括注截断）、
     `excludeChars`（候选行排除字符）；
3. **节次/周次**：`sectionsPattern`（两个捕获组）+ `weeksPattern`（第一组含「周」与
   可选单双尾注）；`sectionsPattern` 留空 = 卡面无节次（截图路径由占用网格回填）；
4. **修复机制**（解释器内置，规则包作者无需关心，但要知道它们的存在）：
   - 标题与标记被拆成两行（"电工电子技术基础B" + "(理论) 教师【周次】"）→ 拼回开新块；
   - 首块建立前标题断行（"太极拳" + "★"、"体育…（跆拳" + "I)★"）→ 拼回开块；
   - 标题与教师粘连成一行 → 宽松 courseStart 规则命中，剩余部分交给字段规则。

判断口诀：**「换个学校它还成立吗？」成立 → 解释器；只对特定系统成立 → 规则包。**

## 常见 OCR 高频变体（写正则时必须兼容）

- 冒号 `:` 常被识别成全角 `：`/中点，甚至整个读成**空格**——键值式的分隔符写全
  `:：·・ `；图标行式的图标常被读成 `©`/`1`/`上` 或整个丢失——行形状规则兜底；
- 圆圈标记 `○`（实验）被识别为 `〇`/`O`/`0` → courseStart 别名规则（行尾 0 需防误判守卫）；
- 属性区换行会切断字段（"校区:下\n沙"）→ 正文拼接后匹配，正则**不要依赖换行**；
- 全角/半角括号混排：正文归一 `（→(`，正则写半角；地点尾注 `(新校区)`/`(光学)`/
  `（智慧教室）` 由 `splitCampus` 的剥尾括注处理；
- 教师职称括注可嵌套（"张三(高等学校教师/未详职称(高校教师))"）→ `cleanTeacher`
  从首个职称括注整体截断，无需规则处理；
- 强智周次分隔符多变体：`【2-4,6,11-13,15-18周】`、`【1-4.6周】`（逗号→句点）、
  `【3,7-10,12-14周】` → `WEEKS_PATTERN_MULTI` 已覆盖；`(双)/(单)` 尾注必须留在
  周次片段里（正则第一组含「周」及尾注），否则单双周丢失；
- 教务网页网格行高不均、合并单元格文字偏下——占用识别按文字块聚类，规则包作者
  无需关心，但手动核对时别对行高差异感到意外。

## 指纹（match.anyOf）怎么选

选「这个系统必然出现、别的系统很少出现」的子串，minHits=2 起步：

- 正方：字段 key 本身（`校区:` `教学班组成` `选课备注`）；
- 正方网页：职称固定文案（`高等学校教师`）、表头（`时间段`）；
- App 课程卡：`智慧教室`、底栏（`日程`）；
- 强智：`(理论)` `(实践)` `【`；
- 学期编号 `(2026-2027-1)-` 会随年份失效，**不要用它做指纹**；
- 新截图包务必与既有截图包做指纹互斥检查（两条样本互相跑对方的 anyOf）。

## 调试技巧

- `python validate.py rulepack.json --simulate cells.txt` 本地试跑（cells.txt 即应用
  私有目录的 `ocr_debug_image.txt` / `ocr_debug.txt` 里的逐格文本段）；
- 应用内「我的 → 解析规则包」可查看每个包的指纹词条；同 id 重新导入即覆盖；
- PDF 导入的 `ocr_debug.txt` / 截图导入的 `ocr_debug_image.txt` 含**规则命中轨迹**
  （哪条规则、哪个字段、值是什么、哪些行未入块）与结构诊断（行列边界），
  规则修不动的问题先看轨迹：字段错 → 改判据；文本就不对 → 占用/OCR 层问题；
- 截图识别路径：先确认「课表对比」功能里同一张截图的占用格识别是正确的。
